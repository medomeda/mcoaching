# PWA Mentora (installation, mises à jour, push) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendre l'application Mentora installable, détecter les nouvelles versions après chaque déploiement, et envoyer des notifications push dont l'écran verrouillé n'affiche que le type d'événement.

**Architecture:** Service worker écrit à la main et servi par une route `/sw.js` (identifiant de build injecté, rien de privé en cache). Un gestionnaire client enregistre le worker et propose les mises à jour sans recharger de force. Le push s'accroche à `notify()` : un collecteur par appel consigne les identifiants de notifications, et l'envoi (après la fin de l'appel ou de la tâche) relit ces notifications dans la base.

**Tech Stack:** Next 15 (App Router, standalone), React 19, Drizzle/PostgreSQL, `web-push` (nouvelle dépendance), `sonner` (déjà là), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-pwa-design.md`

## Global Constraints

- Périmètre : l'application principale (`src/`). Pas le site (`site/`). **Aucun service worker ni push en mode démo** (`NEXT_PUBLIC_DEMO_MODE=true`).
- Manifeste : `display: "standalone"`, `theme_color: "#0e2340"`, `background_color: "#f5f7fa"`, icônes 192×192, 512×512 (`any`) et 512×512 (`maskable`), `start_url: "/"`, `scope: "/"`, `lang: "fr"`. Nom : nom de la plateforme des paramètres de l'instance (« Mentora » par défaut).
- `/sw.js` : `Cache-Control: no-cache, no-store, must-revalidate` et `Content-Security-Policy: default-src 'self'; script-src 'self'`. Enregistré avec `{ scope: "/", updateViaCache: "none" }`, **en production seulement** (en développement : désinscrire les workers existants).
- Cache du worker : uniquement `/_next/static/` et `/icons/` (cache d'abord) ; pages (navigation) toujours par le réseau avec `/offline` en secours ; tout le reste (`/api/*`, RPC, pièces jointes) non intercepté. Préfixe de cache : `mentora-static-<version>`.
- Mises à jour : vérification à l'ouverture, au retour sur l'application (`visibilitychange`) et toutes les `60 * 60 * 1000` ms. Message exact : titre « Nouvelle version disponible », bouton « Mettre à jour », description « Mettez à jour pour profiter des dernières améliorations. » ; jamais de rechargement sans accord ; un seul rechargement.
- Identifiant de build : `SOURCE_COMMIT` (12 premiers caractères), sinon horodatage ; variable `MENTORA_BUILD_ID` injectée par `next.config.ts`.
- Push : variables `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` ; clés absentes = fonction « non disponible », sans erreur. Un interrupteur par appareil, tous les types de notification. **Texte de l'écran verrouillé : le type seulement** (table de la section 3 du spec), corps « Ouvrez {nom de la plateforme} pour les détails. », jamais de nom, titre de demande ni extrait de message. Aucun push si l'instance est suspendue ou si le destinataire n'est pas `ACTIVE`. Un échec d'envoi ne remonte jamais à l'appelant. Abonnement supprimé sur réponse 404 ou 410. `TTL` d'envoi : 24 h.
- Langue de l'interface : français, avec tous les accents.
- Commits : un par tâche, message en français, terminé par `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Appareil partagé** : une autre personne se connecte sur un appareil déjà abonné → l'abonnement lui est réattribué, l'ancien compte ne reçoit plus rien (Task 5).
2. **Opération annulée** : une transaction qui échoue après `notify()` n'envoie aucun push (Task 6).
3. **Contenu privé** : le texte d'un push ne contient ni titre de demande, ni nom, ni extrait de message, pour chacun des 16 types (Task 6).
4. **Clés VAPID absentes** : aucune erreur, état « non disponible », aucun envoi (Tasks 5 et 6).
5. **Instance ou compte suspendu** : aucun push (Task 6). Et à la déconnexion, l'appareil est retiré du serveur avant la fin de session (Task 7).
